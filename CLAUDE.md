# VladCity — правила проекта для Claude Code

Браузерный градостроитель-мегаполис, где каждый житель — агент. Источник правды по дизайну
и порядку работы — [`docs/GDD.md`](docs/GDD.md). Прочитай его перед началом любой фазы.

## Роли и язык

- Владелец проекта — геймдизайнер и тестировщик, не программист. Claude Code — программист.
- Общение, описания PR, документы в `docs/` — по-русски, простыми словами, без жаргона там, где можно обойтись.
- Код, комментарии в коде и сообщения коммитов — по-английски.
- Тексты интерфейса игры — через локализацию ru/it (с фазы 2). Служебные страницы (бенчмарк) — по-русски.

## Как ведём фазы

1. Одна фаза = одна ветка = один pull request. Ничего «на потом» внутри фазы.
2. Фаза закрыта, только когда выполнен её пункт «Готово, когда» из GDD — и это проверено.
3. Результаты замеров и принятые решения записываются в `docs/` (см. `docs/benchmarks.md`).
   Если решение меняет дизайн — правим `docs/GDD.md`, чтобы он оставался источником правды.
4. Найденные проблемы — задачи (issues) на GitHub.

## Архитектура (не нарушать)

- **Симуляция отделена от рендера.** Rust-код в `sim/` не знает о браузере и графике;
  его можно гонять нативно в тестах и бенчмарках.
- **Детерминизм.** Фиксированный тик, свой генератор случайных чисел, никакого `HashMap`
  с недетерминированным порядком в логике симуляции, никакого чтения часов внутри тика.
  Контрольные суммы состояния native == WASM проверяются в CI (`scripts/check-determinism.sh`).
- **Всё, что зависит от страны, — данные, а не код** (`data/`). Это же основа для модов.
- **Уровни детализации симуляции**: каждый житель существует как данные, но обновляется
  с разной частотой. Бюджеты агентов — в `docs/benchmarks.md`.
- **Сайт изолирован (COOP/COEP)** ради SharedArrayBuffer. Никаких ресурсов с чужих доменов
  без заголовка CORP: шрифты, скрипты, текстуры — только свои, из сборки.

## Структура

```
sim/            Rust (workspace-члены sim/*). Сейчас: spike-agents — проба фазы 1
client/         TypeScript + Vite + Babylon.js
client/public/  статика; .htaccess — заголовки COOP/COEP и типы файлов для хостинга Majordomo (Apache)
data/           пакеты данных стран (пока пусто)
docs/           GDD, результаты бенчмарков, решения
scripts/        сборка WASM, бенчмарки, проверка детерминизма
```

## Команды

```bash
./scripts/build-wasm.sh                 # Rust → WASM (обычная и SIMD-сборка) в client/src/generated/
cargo test --release                    # тесты симуляции
cargo run --release --bin native_bench  # нативный бенчмарк
./scripts/check-determinism.sh          # native и WASM должны давать одинаковые контрольные суммы
cd client && npm ci && npm run dev      # локальный сервер (с заголовками COOP/COEP)
cd client && npm run build              # проверка типов + сборка в client/dist
```

Перед пушем: `cargo fmt --check`, `cargo clippy --release --all-targets -- -D warnings`,
`cargo test --release`, `npm run build` в `client/`. То же самое делает CI.

## Зависимости

- Версии npm-пакетов фиксируются точно (`--save-exact`). Новую зависимость добавляем только
  если без неё заметно хуже, и пишем зачем в PR.
- Babylon.js импортируется по глубоким путям (`@babylonjs/core/...`), а не из индекса пакета,
  чтобы не раздувать сборку. Babylon грузится лениво — стартовая страница должна открываться быстро.
- Rust: stable (см. `rust-toolchain.toml`), без nightly. WASM-интерфейс — простой C ABI
  (`#[unsafe(no_mangle)] extern "C"`), без wasm-bindgen, пока он не понадобится.
